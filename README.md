# SWSE Reference Corpus — agent-ready

Star Wars Saga Edition rules data from three incompatible raw sources, rebuilt into one
deduplicated, cross-referenced, chunked corpus with typed records, a link registry, a
search index, and generated indexes. **An agent can answer rules questions from this repo
without network access** — and can prove when the answer is *not* in the corpus.

If you are an agent, read [`AGENTS.md`](AGENTS.md) (the playbook) and open
[`index/INDEX.md`](index/INDEX.md) first. If you are a human reviewing the design, read
[`docs/MAPPING.md`](docs/MAPPING.md) and [`docs/AUDIT.md`](docs/AUDIT.md).

## Why these layers exist

| problem in the raw upload | what the build does | measured effect |
| --- | --- | --- |
| 151/1,074 files were byte-identical duplicates of other pages (crawl followed redirects) | one file per canonical URL; duplicates recorded as `same_as` pointers | 1,074 → 923 pages |
| 44% of all bytes were `[text](https://swse.miraheze.org/wiki/… "text")` link markup | rewrite to `[[Wiki_Slug]]`; drop comment/CDN/redlink noise | 3.00 M → 1.28 M tokens (−57%) |
| 44 `Category:*` "pages" were whole campaign books in one file (largest 637 KB, 285 sections) | split into per-section files, parent keeps an index | every file readable in one Read |
| 51,361 links, 78% of targets absent from the crawl | resolve what is resolvable (redirects, anchors, title/slug match), registry the rest as gaps | 1,201 resolved, 4,198 gap rows |
| three sources naming the same thing differently, and disagreeing | alias lexicon + merged entity records with per-field provenance and diff severity | 4,802 aliases, 1,589 multi-source entities, 533 diffs |
| no way to know whether "no results" means "no rule" | `coverage.md` + `crawl-backlog.md` + a `gap` row per missing target | absence is queryable |

## Quick start

```bash
python3 build/build.py                      # rebuild everything from raw (~11 s, stdlib only, deterministic)
python3 build/query.py stats                # corpus summary as JSON
python3 build/query.py lookup "Toughness"   # exact rules record + file:line citation
python3 build/query.py class Soldier        # one page for whole-class build questions
python3 build/query.py search "flat-footed" # FTS5 prose search
python3 build/query.py gap Base_Attack_Bonus  # is this absence in the crawl or in the game?
python3 build/query.py sql "SELECT name FROM entity WHERE type='feat' AND prerequisites LIKE '%Dexterity 13%' LIMIT 5"
```

Nothing needs installing: Python 3.11+ standard library only (`sqlite3` with FTS5, `zipfile`
for the spreadsheets). The derived layers are committed, so a fresh clone is immediately usable.

## Guarantees the derived layers make

* **Provenance survives.** Every normalized page carries the raw file, `source_url`,
  `canonical_url`, `revision_id` and `content_sha256`; every entity field carries a source
  (`wiki` / `master_reference` / `sagaforge`) and a `file:line` citation.
* **Citations are real.** Chunk and field citations point at files in `normalized/` with
  in-range line spans — checked on every build (`verify` fails the build otherwise).
* **Nothing is hidden.** Ambiguous resolutions are *marked*, not silently accepted
  (`resolved-by:variant-name`, confidence `medium`); approximate matches stay in the gap
  registry and the crawl backlog.
* **Rebuilding is idempotent and verified** — 30+ golden lookups, structural invariants, and
  index/JSONL cross-checks run as the last build stage (`--stage verify`).

## Known limits (say these, don't work around them)

* **Coverage is uneven by design of the crawl.** Feats, talents, talent trees, species and
  force powers are deep; equipment, starships, vehicles, droids and worlds are index-only
  (`index/coverage.md` has per-family numbers, `index/crawl-backlog.md` the priority list).
* **Item statistics** (damage, cost, weight) are largely absent: the chapter pages that
  reference them were crawled, the stat tables behind their links were not.
* **`docs/AUDIT.md` §6** lists the highest-leverage next steps, starting with re-crawling the
  top ~120 backlog targets — that is a crawler-config change, not a data-model change.
